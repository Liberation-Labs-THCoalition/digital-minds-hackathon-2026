There's a tool that can read what a language model is thinking — not perfectly, but well enough to matter. Point it at a dense model, and it can tell you, layer by layer, what the model's internal state is actually about to say. We wanted to know if it still works once the model isn't dense anymore.

Modern large models increasingly route each token through a handful of specialists chosen from a much bigger pool — mixture of experts, not one continuous computation. We pointed our reading tool at a real mixture-of-experts model and asked it the simplest possible question first: can you even tell what comes next?

We built a simple check first: eight easy prompts, the kind any model finishes without thinking, testing whether our tool could tell what came next at all. The check itself turned out to be broken — comparing against a placeholder answer instead of the model's real one. We pulled that number rather than let a broken instrument stand in for a real result.

So we tried to make it smarter. We conditioned the reading on which experts a token actually routed through, on the theory that averaging across very different computational paths was destroying the signal. That didn't help — the conditioned version performed the same as one built on randomly grouped data. We tried a different mathematical approach, weighting the reconstruction by the model's own routing decisions. Same result. Three independent methods, the same wall.

One number in our own draft turned out to be mislabeled along the way — a score reported as a similarity measurement that was actually a pass-fail sanity check. Corrected, and reported here rather than left standing.

So we built the real test: the same depth sweep, run on a dense model with no expert routing at all, layer for layer against the mixture-of-experts curve. If routing is what's breaking the tool, the two curves should look nothing alike. If depth is what's breaking it — if both architectures are just quiet until late and loud near the end — they should move together almost exactly. We built the comparison specifically so it could come out either way. What matters here isn't which one we expected. It's that we finally built a test that could actually tell us.
